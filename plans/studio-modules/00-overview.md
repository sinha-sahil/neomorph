# Studio Module Decomposition — Overview

## Sync note (2026-06-07)

This plan **shipped**. The decomposition is in `packages/studio/src/lib/modules/{connection,tokens,inspector,canvas,export,shell}`; the old `lib/studio/` monolith and the 881-line `+page.svelte` are gone (`src/routes/+page.svelte` is now a thin composer importing `Studio` from `$lib/modules/shell`). Quality gate is green (`check` 0/0, `lint`, `build`) and every hand-written `src` file is < 200 lines.

Two real divergences from the plan as written:

- **The `shared` module was dropped.** Icons are imported per-file (`import x from '$lib/assets/icons/x.svg?url'`, rendered via the library `Img` component) and Studio chrome theme CSS lives in `packages/studio/src/lib/theme/`. So the dependency rule is simply: **feature modules import only `connection`**.
- **The planned hand-written `connection/decoders.ts` shipped as codegen instead.** Wire types *and* their runtime decoders are generated by `type-crafter` from `packages/studio/types/index.yaml` into `packages/studio/src/generated/types` (`$generated` alias), built on `type-decoder`. There is no hand-written `decoders.ts`.

## Goal

Break the monolithic `packages/studio/src/lib/studio/` into focused **standalone client
modules**, each with one clear purpose and a minimal public surface (`index.ts`), following the
skulls `client-module` pattern (`modules/<name>/`).

## Why

Today `lib/studio/` is one module holding five unrelated domains. Symptoms:

- Oversized files (house limit is 200 lines): `ui/Inspector.svelte` 381, `sdk-bridge.ts` 335,
  `store.ts` 272.
- State scattered with no convention (`store.ts`, `selection.ts`, `export.ts`, `canvas/*`).
- No reuse boundaries — nothing can be lifted out and used on its own.

## Modules

Each is independently meaningful and usable given the core. **No decomposition for its own sake.**

| Module | Purpose (standalone value) |
|---|---|
| `connection` (core) | Connect to a target app's CSS variables via Loomer/Weaver: scrape, apply overrides, hold the applied-theme state. Usable headless. |
| `tokens` | Browse & edit a target's design tokens (the sidebar). A reusable token panel. |
| `inspector` | Click an element, view & restyle its computed styles (hybrid token/element edit). A reusable inspector panel. |
| `canvas` | Infinite pan/zoom canvas hosting the target iframe, with tools + device frames. A reusable canvas. |
| `export` | Serialize the applied overrides to copy/download CSS (and later DTCG/JSON). |
| `shell` | App composition only — wires the modules together (layout, top bar, status bar). Not reusable; it's the app. |
| ~~`shared`~~ | ~~Icons + theme CSS used across modules.~~ **Dropped — see Sync note.** Icons are imported per-file via `?url`; theme CSS lives in `lib/theme/`. |

## Dependency rule (keeps modules standalone)

Feature modules import **only `connection`** (the `shared` module was dropped), never each other.
`export` reads overrides from `connection` (not from `tokens`/`inspector`). `shell` composes everything.

```
            connection  (bridge + scrape + overrides + types)
          ↗     ↑      ↑     ↖
     tokens inspector canvas export
                   ↑
                 shell
```

## Success criteria

- Every `src` file < 200 lines.
- Each module has an `index.ts` minimal API; zero feature↔feature imports.
- Pure reorg — **no behavior change**.
- `pnpm --filter @neomorph/studio check && lint && build` green; in-browser smoke test passes.
